# 无障碍（a11y）

> 本文管：axe 的判定口径（哪些算红）、棘轮基线怎么维护、键盘与焦点环的硬要求、`prefers-reduced-motion` 的三条禁止、以及「contrast incomplete 不算通过」这条最容易放水的判据。
> **必读时机**：改任何交互组件、加/改 focus 样式、动 `--color-ring-focus`、改文档页结构、或 `a11y smoke` / `visual` 里的 docs a11y 红了。
> 与 `rules/component-api.md` §6 分工：那边说「组件必须带什么 a11y props」，这边说「怎么验证、什么算过」。
> 与 `docs/DESIGN.md` 附录 B 分工：那边是**对比度口径与豁免依据**（哪个色对哪个色要多少比），这边是**自动门禁的判据边界**。
> 判据真源是 `e2e/design-atoms.a11y.spec.ts` / `design-atom-docs.a11y.spec.ts` / `design-component-docs.a11y.spec.ts` / `export-audit.spec.ts` 四个 spec。

## 1. 五条 WCAG tag，不是「整套 WCAG」

所有 axe 调用都用同一份配置：<!-- design-atoms.a11y.spec.ts:runAxe · export-audit.spec.ts:runAxe -->

```js
runOnly: {
  type: "tag",
  values: ["wcag2a", "wcag2aa", "wcag21a", "wcag21aa", "wcag22aa"],
},
resultTypes: ["violations", "incomplete"],
```

覆盖 **WCAG 2.0 / 2.1 / 2.2 的 A + AA 级**。**不含 AAA**，也不含 `best-practice` tag。

这意味着：axe 报绿 **不等于**「无障碍做好了」，只等于「这五个 tag 覆盖的规则里没有违规」。像 landmarks 唯一性、heading 顺序、region 这类属于 `best-practice` 的规则，axe 这条门禁**不管**——它们靠 `verify-atom-docs` 的结构断言（7 个 section、无空表）和人工评审兜。

## 2. 判定分三档：serious/critical 红、moderate 记账、minor 只报告

| impact | 处置 | 在哪里 |
|---|---|---|
| `critical` / `serious` | **门禁红** | `expect(serious).toEqual([])` |
| `moderate` | 记录进报告，不判红 | `axe-moderate-summary` 逐条列出 + attach json |
| `minor` | 只打印计数 | `console.log` 一行 |

三档都要打印出来，不是只报红的那部分：<!-- design-atoms.a11y.spec.ts:axe 循环 -->

```js
console.log(`[axe] ${theme}@${width}: serious/critical=${serious.length} moderate=${moderate.length} minor=${minor.length} incomplete=${incomplete.length} (contrast=${contrastIncomplete.length})`);
```

**为什么 moderate 不判红却不忽略**：moderate 里混着真问题和「这条规则对本项目不适用」两种情况，逐条判断需要人。全判红会让门禁常年红着（等于失效），全忽略会丢掉真问题。折中是**记录 + 可见**，让它在报告里存在，评审时能翻到。

## 3. `incomplete` 不是通过——contrast 判不出来也算红

```js
// "incomplete" is axe's "cannot determine" bucket — dropping it would let a
// transition/background it cannot parse look like a pass. Keep it in the report.
```

`incomplete` 是 axe 的「算不出来」桶。**把 contrast 的 incomplete 当通过，是这个门禁最容易被放水的地方**——背景是渐变、图片、或半透明时 axe 算不出对比度，如果直接忽略，一个真·低对比的组件会看起来完全合规。

所以在 atoms 和 atom-docs 两个 spec 里：<!-- design-atoms.a11y.spec.ts -->

```js
const contrastIncomplete = incomplete.filter((v) => v.id === "color-contrast");
expect(contrastIncomplete.map(v => `contrast incomplete × ${v.nodes.length}`),
       `axe could not determine contrast at ${theme}@${width}`).toEqual([]);
```

**唯一的例外在旧组件实物上**：`design-component-docs.a11y.spec.ts` 的 `#example` 区域内允许 `color-contrast` 违规——那是 23 个 M2 之前的旧组件的对比度债，逐条记在各自的文档对比度表里。但结构/标签/ARIA 类违规照样不许有。

判据要盯「在哪个区域内」：`#example` 之外（文档版式本身）= 0；`#example` 之内（旧组件实物）= 允许 contrast，其余仍禁。<!-- design-component-docs.a11y.spec.ts 头注释 -->

## 4. 棘轮基线：`axe-known.json` 当前是空数组

`export-audit.spec.ts`（CI 的 `a11y smoke` / `a11y-nightly` 跑的就是它）用的是**棘轮**而不是绝对零：

- 存量违规登记在 `docs/_reviews/M2-12/audit-data/axe-known.json`
- 已登记的不判红，**新增的判红**
- 报告里出现「存量 N 条规则项已登记」字样

**当前状态：三个 `axe-known.json` 全都是 `[]`**（M2-12 / M2-13 / M2-13b 三处）。<!-- 实测 cat docs/_reviews/*/audit-data/axe-known.json -->

也就是说**全站当前 0 条 serious/critical**，棘轮起点是零。这意味着：

- 任何一条新出现的 serious/critical 都会立刻红，没有「反正有存量」的缓冲
- **不要往 `axe-known.json` 里加条目来让门禁变绿**。那个文件是历史债的台账，不是豁免开关。真需要加，必须在 decision-log 里写 D 编号，说明为什么这条规则在本项目不适用、或为什么暂时接受。

## 5. 键盘：Tab 必须按 DOM 顺序走完每一个可聚焦元素

`design-atoms.a11y.spec.ts` 的 `tab order + visible focus ring` 用例做的事：<!-- 该 spec 的 keyboard describe -->

1. 选出所有可聚焦元素（`a[href]`、`button:not([disabled])`、`input:not([disabled])`、`select`、`textarea`、`[tabindex]:not([tabindex="-1"])`），并过滤掉不可见的
2. 给每个打 `data-kbd` 序号
3. 按 Tab 逐个走，记录落点序号
4. 断言 `visited` 与 `expected` **完全相等**——顺序一致、一个不漏、一个不多

硬要求：

- **可聚焦元素必须 > 30 个**（`expect(expected.length).toBeGreaterThan(30)`）——少于这个数说明 fixture 坏了或选择器失效，门禁在空转
- **`disabled` 的控件不可 Tab 到**，也不在计数里
- Tab 落到 fixture 之外就算失败

## 6. 焦点环：≥2px、solid、颜色必须是 token

三条硬断言：<!-- design-atoms.a11y.spec.ts:ringProbe / ringToken -->

| 要求 | 判据 |
|---|---|
| 可见 | `outlineStyle !== "none"` 且 `parseFloat(outlineWidth) >= 2` |
| 实线 | `outline-style === "solid"` |
| 用 token | `outline-color === getComputedStyle(var(--color-ring-focus))` 的解析值 |

**焦点环可以挂在 `.field__control` 包装层**（Input 的既定模式）——`ringProbe` 会先查元素本身，再向上找 `.field__control`。这是唯一允许的间接层，其他组件必须自己带环。

**颜色比对是比解析后的 rgb 值**，不是比字符串。所以 token 一旦回归成低对比色，这里会红——和视觉基线双重拦截。

## 7. 键盘交互：Enter / Space / Esc 要在真控件上验

不是查有没有绑定事件，是**真的按键看效果**：

- Space 切 `aria-pressed`（`false → true`）
- Enter 在内部链接上真的发生导航（等 `waitForLoadState`）
- Esc 在输入框里按了之后，页面结构不崩（`[data-specimen]` 仍是 12 个）
- 重载后输入框仍能打字

**为什么要这样测**：绑了 handler 但 `preventDefault` 写错、或 `keydown` 绑在了不可聚焦的容器上，静态检查看不出来，真按键才能暴露。

## 8. `prefers-reduced-motion: reduce` 的三条禁止

启用 `reducedMotion: "reduce"` 后，在 `[data-specimen] *` 范围内断言：<!-- design-atoms.a11y.spec.ts:motion -->

1. **没有 running 动画**：`document.getAnimations().filter(a => a.playState === "running")` 为空
2. **没有 CSS 动画**：`animationName !== "none"` 且 `animationDuration > 0` 的一个都不能有
3. **没有 CSS 过渡**：`transitionProperty !== "none"` 且 `transitionDuration > 0` 的一个都不能有

外加一条几何断言：`:active` 时按钮的 `y` 坐标位移 **< 0.5px**——不许有 `translateY` 之类的按下反馈。

**实现方式**：在 `@media (prefers-reduced-motion: reduce)` 里把 `animation-duration` / `transition-duration` 设成 `0.01ms` 而不是 `none`。fancybox 那类第三方库用这个值正是为了保留 `transitionend` 事件仍在触发（`none` 会让事件永不触发，某些按需初始化的逻辑就死了）。<!-- fancybox-overrides.css:75-78 -->

## 9. 文档页的结构断言（不是 axe，是同批的硬要求）

`design-atom-docs.a11y.spec.ts` 和 `design-component-docs.a11y.spec.ts` 除了 axe 还查结构：<!-- 两个 docs spec 头注释 -->

| 断言 | 判据 |
|---|---|
| 7 个必填 section 都在 | `purpose / props / slots / states / a11y / tokens / example` 各恰好 1 个 |
| 没有空表 | 每张表 `rows.length >= 2` |
| 旧组件文档页每页 5 张表 | `props / slots / states / 对比度 / 尺寸` |
| 示例区有真实组件实例 | `#example` 里至少一个画框 |
| 文档版式 0 运行时 JS | 没有 hydration island；内联 `<script>` 只允许来自被展示的组件（23 个旧组件里有 **7 个**自带脚本，逐条登记在 `COMPONENTS_WITH_SCRIPT`：typewritertext 1 / notice 1 / watermark 1 / walinecomment 1 / search 2 / hitokoto 1 / donate 1 段） |
| 390px 无横向溢出 | 宽表自己滚动，不撑破页面 |

**「文档版式 0 运行时 JS」是设计约束不是性能优化**：文档页是给人读规格的，不该带交互逻辑。旧组件自带脚本是既有事实，所以用白名单列出，不是干脆不查。

## 10. 改了东西之后跑什么

| 改了什么 | 跑什么 |
|---|---|
| atom / molecule 组件 | `npx playwright test e2e/design-atoms.a11y.spec.ts` |
| 12 个 atom 的文档页 | `... e2e/design-atom-docs.a11y.spec.ts` |
| 23 个旧组件或其文档 | `... e2e/design-component-docs.a11y.spec.ts` |
| 全站（路由/布局/主题） | `... e2e/export-audit.spec.ts`（全量约 30–40 分钟，单 worker） |
| 只查几个路由 | `AUDIT_ROUTES='/ /blog/1/ /culture/' npx playwright test e2e/export-audit.spec.ts` |

**别用「本地跑过了」当证据**——门禁的结论必须是命令输出或 CI run，这与 `AGENTS.md` 的验证纪律一致。

## 11. 报告落在哪

| 来源 | 路径 |
|---|---|
| atoms axe | `test-results/axe-atoms/<theme>-<width>.json` |
| atom docs axe | `test-results/axe-atom-docs/<slug>-<theme>.json` |
| 全站审计 | `docs/_reviews/M2-12/audit-data/{dark-pages,axe,mobile}.jsonl` |

**per-run json 落盘而不是只 attach**，是因为 module state 不跨 worker，而文件跨——`axe-moderate-summary` 那个用例就是从磁盘读回 12 份 json 再汇总的。
